# impodee

# อิ่มพอดี · calorie buddy

เว็บแอปคำนวณแคลอรี่และบันทึกมื้ออาหาร หน้าเดียวจบ มินิมอลสามธีม
สมัครสมาชิกด้วย **ชื่อกับรหัส** เท่านั้น ไม่ต้องใช้อีเมล

## เริ่มใช้งาน

```bash
bun install
bun dev            # http://localhost:3000
```

คำสั่งอื่น

```bash
bun run build      # build production
bun start          # รัน production
bun run lint       # ESLint
bun test           # ชุดทดสอบ (109 เทสต์)
```

## ฟีเจอร์

### คำนวณเป้าหมาย

- **BMR** ด้วยสูตร Mifflin-St Jeor แล้วคูณตัวคูณกิจกรรมเป็น **TDEE**
- ปรับตามเป้าหมาย — ลดน้ำหนัก (−20%) / คงน้ำหนัก / เพิ่มน้ำหนัก (+15%)
  พร้อมกันไม่ให้ต่ำกว่าขั้นต่ำที่ปลอดภัย (หญิง 1200 · ชาย 1500 kcal)
- สัดส่วน **โปรตีน / คาร์บ / ไขมัน** เป็นกรัม แสดงเป็นโดนัทชาร์ต
- **BMI** ตามเกณฑ์เอเชีย-แปซิฟิก พร้อมช่วงน้ำหนักที่เหมาะกับส่วนสูง
- ปริมาณน้ำที่ควรดื่มต่อวัน

### บันทึกมื้อวันนี้

- เลือกจากเมนู **~95 รายการ** (อาหารไทย ฟาสต์ฟู้ด ของหวาน เครื่องดื่ม ผลไม้)
  ค้นหาด้วยชื่อ หรือกรองตาม 9 หมวด
- แยกเป็น **มื้อเช้า / กลางวัน / เย็น / ของว่าง** (เดามื้อจากเวลาให้เลย)
- ปรับจำนวนเสิร์ฟทีละครึ่งหน่วย ค่าทั้งหมดคิดใหม่ตามจริง
- วงแหวนบอกว่ากินไปแล้วกี่แคลจากเป้าหมาย **เหลืออีกเท่าไหร่** หรือ **เกินมาเท่าไหร่**
- แถบเทียบโปรตีน/คาร์บ/ไขมันที่กินไปกับที่ควรได้

### ธีม

สลับได้ทันทีจากปุ่มมุมขวาบน สามแบบ — **ขาว-ชมพู · ขาว-ฟ้า · ขาว-เหลือง**
จำไว้ทั้งใน cookie (ไม่มีสีกระพริบตอนโหลด เพราะใส่ `data-theme` ตอน SSR)
และในบัญชี (เปิดจากเครื่องอื่นก็ได้สีเดิม)

## ย้ายไป MongoDB

โค้ดเตรียมไว้ให้ย้ายได้โดยไม่ต้องรื้อ — ทุกส่วนคุยกับ interface `DataStore`
ไม่มีใครเรียก `fs` ตรง ๆ นอกจาก [store.ts](src/lib/db/store.ts)

ใน [src/lib/db/schema.ts](src/lib/db/schema.ts) มีพร้อมแล้ว

- `UserDoc` / `FoodEntryDoc` — รูปร่างเอกสารสองคอลเลกชัน
- `INDEXES` — ส่งเข้า `createIndexes()` ได้ตรง ๆ
  (`nameKey` unique, `{userKey, date}` compound, `entryId` unique)
- `VALIDATORS` — `$jsonSchema` สำหรับ `createCollection()`
- คอมเมนต์ท้ายไฟล์อธิบายสามขั้นที่ต้องทำ

สามขั้นนั้นย่อ ๆ คือ `bun add mongodb` → เขียน `mongo-store.ts` ให้หน้าตาตรงกับ
`DataStore` → เปลี่ยน `getStore()` ให้คืน `mongoStore` **บรรทัดเดียว**

ที่ออกแบบไว้เผื่ออนาคต

- **หนึ่งเอกสารต่อหนึ่งรายการที่กิน** ไม่ใช่หนึ่งเอกสารต่อวัน — เพิ่ม/ลบรายการเดียว
  ไม่ต้องอ่านทั้งวันมาเขียนทับ และ query ข้ามวันได้เลยตอนจะทำกราฟย้อนหลัง
- **ถ่ายสำเนาชื่อกับตัวเลขไว้ตอนบันทึก** ไม่ join กับตารางเมนู
  ถ้าแก้ข้อมูลเมนูวันหลัง ประวัติที่กินไปแล้วจะไม่เปลี่ยนตาม

## เรื่องการอ่านออก (contrast)

ทุกสีที่มีข้อความทับอยู่ผ่านเกณฑ์ **WCAG AA** ทั้งสามธีม และมีเทสต์บังคับไว้
ที่ [tests/contrast.test.ts](tests/contrast.test.ts) — คำนวณ contrast ratio จาก
ตัวแปรใน `globals.css` จริง เพิ่มธีมใหม่แล้วสีอ่านไม่ออกจะเทสต์ตกทันที

- **ปุ่มหลัก** ใช้ไล่สีพาสเทลกับตัวอักษรสีเข้ม (ต่ำสุด 4.90:1)
  ไม่ใช่สีสดกับตัวอักษรขาว เพราะขาวบนชมพู/ฟ้าอ่อนได้แค่ 2.2:1
- **ปุ่มตอน disabled** สลับตัวอักษรเป็น `brand-800` ด้วย ไม่ใช่แค่เปลี่ยนพื้น
- **โลโก้** แยก token `--mark-*` ออกจาก `--cta-*` จึงคงสีสดไว้เป็นจุดเด่นได้
  (เป็นกราฟิกตกแต่ง มีชื่อแอปเป็นตัวหนังสืออยู่ใต้ภาพแล้ว)
- `brand-500/600` อ่อนเกินกว่าจะใช้กับข้อความตัวเล็ก — ในโค้ดใช้แค่กับตัวเลขใหญ่
  (30–44px ซึ่งเกณฑ์คือ 3:1) ข้อความตัวเล็กใช้ `brand-700` ขึ้นไป

## เรื่องความปลอดภัย

- รหัสผ่าน hash ด้วย **scrypt** + salt สุ่มรายคน ไม่เคยเก็บรหัสจริง
- เทียบ hash ด้วย `timingSafeEqual` และทำ hash หลอกกรณีไม่พบผู้ใช้
  เพื่อไม่ให้เวลาตอบบอกได้ว่าชื่อนั้นมีอยู่จริงไหม
- session เป็น cookie เซ็นด้วย **HMAC-SHA256** ตั้ง `httpOnly` + `sameSite=lax`
  และ `secure` เมื่อรันโปรดักชัน — cookie ที่ถูกแก้ไขใช้ไม่ได้
- จำกัดการเดารหัสผิด 8 ครั้ง แล้วล็อก 5 นาที
- **ทุกคำสั่งเกี่ยวกับมื้ออาหารเช็คเจ้าของจาก session** ไม่เชื่อ id ที่ client ส่งมา
  (มีเทสต์ยืนยันว่าผู้ใช้คนอื่นแก้หรือลบรายการของเราไม่ได้)
- เขียนไฟล์แบบ atomic (เขียน `.tmp` แล้ว rename) และต่อคิวกันเขียนทับกัน

### ข้อมูลถูกเก็บที่ไหน

โฟลเดอร์ `data/` (อยู่ใน `.gitignore` แล้ว)

- `data/db.json` — สมาชิกและรายการอาหาร
- `data/.secret` — กุญแจเซ็น session สร้างอัตโนมัติครั้งแรกที่รัน

**ถ้าจะขึ้นโปรดักชันจริง** ตั้ง `AUTH_SECRET` เอง (32 ตัวอักษรขึ้นไป)
เพื่อให้ session ไม่หลุดเวลา deploy ใหม่ และย้ายไป MongoDB ตามด้านบน
เพราะไฟล์ JSON ไม่รอดบน serverless ที่ filesystem อ่านเขียนไม่ถาวร

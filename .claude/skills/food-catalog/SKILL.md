# เพิ่ม/แก้เมนูใน food catalog

เมนูทั้งหมดอยู่ในอาเรย์ `FOODS` ที่ [src/lib/foods.ts](../../../src/lib/foods.ts)

## กฎเหล็ก: kcal ต้องคำนวณ ไม่ใช่ประมาณ

`kcal` ของทุกเมนู **ต้องเท่ากับ** `protein*4 + carbs*4 + fat*9` (คลาดเคลื่อนได้ไม่เกิน 2)

`tests/foods.test.ts` บังคับกฎนี้กับทุกแถว ถ้าใส่ตัวเลขที่ขัดกันเองเทสต์จะตกทันที
พร้อมบอกชื่อเมนูและตัวเลขที่ควรเป็น

ลำดับการทำที่ถูก คือ **เลือกมาโครก่อน แล้วคำนวณ kcal** ไม่ใช่ตั้ง kcal แล้วเดามาโคร

```
protein 30, carbs 80, fat 20  →  30*4 + 80*4 + 20*9 = 620
```

คิดเลขให้แน่ใจก่อนเขียน แล้วรัน `bun test tests/foods.test.ts`

## รูปแบบแถว

```ts
{ id: "khao-man-kai", name: "ข้าวมันไก่", serving: "1 จาน",
  protein: 30, carbs: 80, fat: 20, kcal: 620, category: "onePlate" },
```

- `id` — kebab-case โรมัน ห้ามซ้ำ (มีเทสต์เช็ค) **อย่าเปลี่ยน id ที่มีอยู่แล้ว**
  เพราะ `foodEntries` ที่ผู้ใช้บันทึกไว้อ้าง `foodId` นี้
- `name` / `serving` — ภาษาไทย ระบุหน่วยเสิร์ฟให้ชัด ("1 จาน", "100 ก.", "1 ไม้")
- `category` — ต้องมีอยู่ใน `FOOD_CATEGORIES` แล้ว (เทสต์เช็คสองทาง: ทุกเมนูอยู่ในหมวดจริง
  และทุกหมวดต้องมีเมนูอย่างน้อยหนึ่งอย่าง)

## ลบเมนูต้องระวัง

ประวัติที่ผู้ใช้กินไปแล้ว **ถ่ายสำเนา** ชื่อกับตัวเลขไว้ในเอกสารตัวเอง ไม่ได้ join กับตารางนี้
ลบเมนูออกจึงไม่ทำให้ประวัติเก่าพัง — `setServings` มีทางถอยที่คิดจากค่าต่อเสิร์ฟที่บันทึกไว้
แต่ผู้ใช้จะเพิ่มเมนูนั้นใหม่ไม่ได้

## หมวดใหม่

เพิ่มใน `FOOD_CATEGORIES` แล้วต้องมีเมนูในหมวดนั้นอย่างน้อยหนึ่งอย่าง
ชิปหมวดใน `food-log.tsx` เลื่อนแนวนอนอยู่แล้ว ไม่ต้องแก้ UI

## ตรวจงาน

```bash
bun test tests/foods.test.ts   # กฎ 4/4/9, id ซ้ำ, หมวด, ค่าติดลบ
bun run verify                 # lint + typecheck + ทั้งชุด
```
